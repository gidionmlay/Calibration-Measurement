## 2. Independent Calculation Methodology

To ensure objective verification, an independent reference module was constructed in [`src/utils/calculationValidation.test.ts`](file:///media/sda3/Projects/Calibration/src/utils/calculationValidation.test.ts). This reference module derives all expected intermediate and final quantities from first-principles mathematical formulas without invoking any production calculation functions:

### Governing Mathematical Formulation
1. **Ride Difference ($d_i$):**
   $$d_i = B_i - A_i$$
   Where $A_i$ is start reading and $B_i$ is finish reading. If counter rollover occurs with configured maximum $M$:
   $$d_i = B_i + (M + 1) - A_i$$
2. **Total Calibration Difference ($D$):**
   $$D = \sum_{i=1}^{4} d_i$$
3. **Average Count ($C_{avg}$):**
   $$C_{avg} = \frac{D}{4}$$
4. **Course Length in Kilometres ($L_{km}$):**
   $$L_{km} = \frac{L}{1000}$$
5. **Counts Per Kilometre ($CPK$):**
   $$CPK = \frac{C_{avg}}{L_{km}} = \frac{C_{avg} \times 1000}{L}$$
6. **Working Constant ($WC$):**
   $$WC = CPK \times 1.001$$
   *(Applies the mandatory $0.1\%$ Short Course Prevention Factor).*
7. **Total Course Count ($T$):**
   $$T = F - S \quad (\text{or } F + (M + 1) - S \text{ with rollover})$$
8. **Measured Course Distance:**
   $$\text{Distance (km)} = \frac{T}{WC_{applicable}}$$

## 3. Reference Cases with Worked Calculations

### Primary Reference Case: 200 m Calibration Course
- **Input Parameters:**
  - Course Length: $L = 200\text{ m}$
  - Course Length (km): $L_{km} = 0.2\text{ km}$
  - Starting counter reading ($A_1$): $11082$
  - Finish readings ($B_1, B_2, B_3, B_4$): $12021, 13042, 14052, 15052$
- **Step-by-Step Worked Derivation:**
  - **Ride 1:** $d_1 = 12021 - 11082 = 939$ counts
  - **Ride 2:** (Sequential link $A_2 = B_1 = 12021$) $\implies d_2 = 13042 - 12021 = 1021$ counts
  - **Ride 3:** (Sequential link $A_3 = B_2 = 13042$) $\implies d_3 = 14052 - 13042 = 1010$ counts
  - **Ride 4:** (Sequential link $A_4 = B_3 = 14052$) $\implies d_4 = 15052 - 14052 = 1000$ counts
  - **Total Count ($D$):**
    $$D = 939 + 1021 + 1010 + 1000 = 3970\text{ counts}$$
  - **Average Count ($C_{avg}$):**
    $$C_{avg} = \frac{3970}{4} = 992.5\text{ counts}$$
  - **Counts Per Kilometre ($CPK$):**
    $$CPK = \frac{992.5}{0.2} = 4962.5\text{ counts/km}$$
  - **Pre-Calibration Working Constant ($WC$):**
    $$WC = 4962.5 \times 1.001 = 4967.4625\text{ counts/km}$$
  - **Spread Metrics:**
    - High Ride: Ride 2 ($1021$ counts)
    - Low Ride: Ride 1 ($939$ counts)
    - Spread Range: $1021 - 939 = 82\text{ counts}$

### Course Distance Measurement Example
- **Input Readings:**
  - Start Reading ($S$): $124002$
  - Finish Reading ($F$): $320456$
  - Governing Constant: $WC = 4967.4625$
- **Step-by-Step Worked Derivation:**
  - **Course Count ($T$):**
    $$T = 320456 - 124002 = 196454\text{ counts}$$

## 5. Edge-Case and Policy-Enforcement Results

The independent test suite evaluated 16 distinct numerical and workflow edge cases:

### A. Arithmetic Edge Cases
1. **Zero Ride Difference ($F = S$):** Correctly returns count $= 0$, adjustment $= 0$.
2. **Negative Difference with Rollover `none`:** Correctly rejected with explicit error message (`"non-wrapping"`).
3. **Negative Difference with Rollover `notConfigured`:** Correctly rejected with directive to configure in Setup.
4. **Negative Difference with Rollover `wrap` (6-digit, 999999 max):**
   - Start: $999980$, Finish: $20 \implies 20 + 1000000 - 999980 = 40$ counts.
   - Result: Exactly verified as count $= 40$, adjustment $= 1000000$.
5. **Reading Exceeding Rollover Max:** Start $1000005$ on $999999$ counter is cleanly rejected.
6. **Course Length Validations:**
   - Zero (`0`): Rejected with reason `notPositive`.
   - Negative (`-200`): Rejected with reason `notPositive`.
   - Alphabetic/Malformed (`200m`, `abc`): Rejected with reason `invalid`.
   - Decimals (`333.333`): Accepted and parsed accurately.
   - Extremely Small (`0.001 m`): Yields $10^9$ counts/km without floating-point crash.
   - Unusually Large (`50000 m`): Handled safely without numerical overflow.
7. **Reading Parsing Validations:**
   - Whole digits only (`0`, `124002`) accepted.
   - Decimals (`124002.5`) rejected (Jones counter displays discrete integer counts).
   - Negative numbers (`-100`) rejected.
   - Blank/whitespace strings rejected with reason `missing`.
8. **Large Readings & Safe Integer Limit:**
   - Up to $10^9$ counts tested; completely within `Number.MAX_SAFE_INTEGER` ($9.007 \times 10^{15}$).
9. **Division-by-Zero Protection:**
   - When $WC = 0$ or `null`, `computeDistance()` safely produces `km: null` without `Infinity` or `NaN`.

### B. Dependency & Invalidation Mechanics
1. **Sequential Start Linkage:** Finish of Ride $i$ automatically sets start of Ride $i+1$.
2. **Explicit Override:** Unlinking Ride $i$ start allows custom entry and captures required `overrideReason`.
3. **Review Invalidation & Signature Hashing:**
   - **Intermediate Finish Edits:** Modifying Ride 1 finish ($12021 \to 12025$) increases Ride 1 count by $+4$ and decreases linked Ride 2 count by $-4$. The sum $D = 3970$ is unchanged. The `pre` review is correctly invalidated (stale) because raw inputs changed, while `comparison` review remains current because $WC$ was preserved.
   - **Terminal Finish Edits:** Modifying Ride 4 finish ($15052 \to 15060$) changes total $D$ and $WC_{pre}$, correctly invalidating both `pre` and `comparison` reviews.
   - **Governing Constant Edits:** Modifying post-calibration readings when Post WC is the governing constant invalidates `distance` review.
   - **Checklist Blocker Enforcement:** Any stale review immediately trips the `current` checklist item, blocking finalization.

### C. Policy-Dependent Constant Resolution (DEF-02 Safeguards)
1. **Incomplete Post-Calibration:** Falls back to provisional Pre WC (`source: 'pre', provisional: true, reasons: ['postIncomplete']`).
2. **Rule `notConfigured`:** Uses Pre WC provisionally, flags `ruleNotConfigured`, and trips checklist blocker `finalRule`.
3. **Rule `larger`:**
   - When Post WC ($5005.0$) > Pre WC ($4967.4625$), distance uses $5005.0$.
   - When Pre WC ($4967.4625$) > Post WC ($4950.0$), distance uses $4967.4625$.
   - Flags `ruleNotApproved` while policy remains unratified.
4. **Rule `average`:** Calculates exact arithmetic mean $\frac{Pre + Post}{2}$.
5. **Finalization Safeguard:** Default `policy` parameter in [`deriveSession()`](file:///media/sda3/Projects/Calibration/src/utils/sessionRules.ts) sets `policyApproval` blocker to `ok: false`, permanently preventing finalization bypass through direct API calls or UI interactions.

## 6. Precision and Rounding Findings

- **Internal Numeric Representation:**
  - Calculations execute using standard JavaScript 64-bit binary floating-point arithmetic (IEEE 754 double precision, 53 mantissa bits).
  - Internal calculations maintain $\approx 15\text{--}17$ significant decimal digits of precision.
- **Mitigation of Binary Representation Noise:**
  - In `computeCalibration()`, $CPK$ is computed as:
    $$\text{Average} \times 1000 \div \text{courseLengthM}$$
    This algebraic arrangement avoids dividing by decimal fractions like $0.2$, which have non-terminating binary representations ($0.00110011\dots_2$), eliminating spurious binary rounding noise (e.g. `4962.5` instead of `4962.500000000001`).
- **Rounding Boundaries:**
  - No intermediate rounding occurs in ride counts, sums, CPK, working constants, or distances.
  - Rounding occurs **only at the presentation layer**:
    - Working constants: Formatted to 4 decimal places via `fmt(wc, 4)` (`4967.4625`).
    - Distances: Formatted to 3 decimal places via `fmt(km, 3)` (`39.548 km`).
- **Export Representation:**
  - Full numeric precision is exported in structured JSON (`results.distanceKm: 39.54815964887823`, `results.preWC: 4967.4625`) alongside formatted display strings (`results.distanceDisplay: "39.548"`).
  - Reports display both rounded distance and full precision: `"39.548 km (Full precision: 39.54815964887823)"`.

## 7. Defects and Regression Verification

During Phase 8 independent calculation validation, zero mathematical defects or formula errors were detected. 

### Key Engineering Verification Findings:
1. **Cancellation Property in Sequential Linkage:**
   When rides are sequentially linked without overrides, intermediate finish readings cancel out in the telescoping sum $\sum (B_i - A_i) = B_4 - A_1$. The signature hashing in `deriveSession()` correctly tracks both:
   - Raw ride readings in `signatures.pre` (invalidating Pre review on any reading edit).
   - Calculated constants in `signatures.comparison` (invalidating Comparison review only when total $WC$ changes).
2. **Provisional Notice Consistency:**
   Every export format (Text report, JSON report, HTML modal, Print stylesheet) embeds `PROVISIONAL — NOT FOR OFFICIAL CERTIFICATION` and explicitly enumerates unratified policies MP-01 through MP-09.
