## 1. Executive Summary

Phase 2 addressed two critical defects identified during the initial baseline audit:
1. **DEF-02 (Calculation Defect):** Course distance was permanently hardcoded to use the pre-calibration working constant (`pre.wc`), completely disconnected from the operator's configured final-constant selection rule and post-calibration outcome.
2. **DEF-01 (Data Loss Defect):** Complete absence of disk persistence. All session data, overrides, and audit events were stored in volatile React component state and lost immediately upon browser refresh or tab close.

In addition, Phase 2 strictly adhered to the non-negotiable measurement policy constraint: because the governing road-measurement standard and final-constant rule have not been officially ratified by the measurement authority, all provisional calculations are explicitly labeled as such in the user interface, and official finalization is guarded until authorized policy approval is codified.

Finally, `src/package.json` was verified to be a redundant artifact generated by the prototyping tool and safely removed.

## 2. Calculation Defect Remediation (Part B)

### 2.1 Problem Diagnosis
In the prototype baseline:
- `src/utils/sessionRules.ts` line 117 computed distance via: `computeDistance(s.distStart, s.distFinish, pre.wc, rollover)`
- `src/pages/CourseDistance.tsx` line 23 extracted `const wc = derived.pre.wc`
- `src/utils/audit.ts` computed distance results solely from `pre.wc`
- Downstream review signature hashing in `sessionRules.ts` checked only `pre.wc`, meaning changes to the final constant rule or post-calibration readings never invalidated the distance review.

### 2.2 Authoritative Architecture
A single, testable calculation path was introduced:
- **`resolveApplicableConstant(rule, preWC, postWC, isApproved)` in `src/utils/calibration.ts`**:
  - Implements the authoritative determination of the governing working constant.
  - Returns a structured `ConstantBasis`:
    ```typescript
    export interface ConstantBasis {
      wc: number | null;
      source: 'none' | 'pre' | 'final';
      provisional: boolean;
      reasons: ('preIncomplete' | 'postIncomplete' | 'ruleNotConfigured' | 'ruleNotApproved')[];
    }
    ```
- **Dynamic Propagation**:
  - If pre-calibration is incomplete, no constant is available (`source: 'none'`).
  - If post-calibration is incomplete or the final rule is `notConfigured`, distance provisionally uses `pre.wc` (`source: 'pre'`, `provisional: true`).
  - When post-calibration is complete and a rule (`larger` or `average`) is configured, distance dynamically evaluates with that constant (`source: 'final'`).
  - While governing policy approval remains pending, all results are explicitly marked `provisional: true`.
- **UI & Review Consistency**:
  - `CourseDistance.tsx`, `ResultsSummary.tsx`, `RecordSections.tsx`, and `ReportPreview.tsx` all consume `derived.distance.basis` and display the governing constant and provisional status.
  - Signature hashing for distance incorporates `applicableBasis.wc`, ensuring modifying the final rule or post-calibration readings that change the governing constant immediately flips `reviews.distance` to `'stale'`.
  - Recalculation and invalidation audit events are appended without duplicates.

## 3. Governing Measurement Policy Analysis & Non-Negotiable Constraints

### 3.1 Behavior of Final-Constant Options
| Option | Pre-Cal Only | Post-Cal Complete | Governing Constant Value | Status | Finalization Blocked? |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`notConfigured`** | Pre WC | Pre WC | `pre.wc` (provisional fallback) | Provisional | **Yes** (blocker: `finalRule` & `policyApproval`) |
| **`larger`** | Pre WC | $\max(\text{pre}, \text{post})$ | Larger of Pre and Post WC | Provisional | **Yes** (blocker: `policyApproval`) |
| **`average`** | Pre WC | $\frac{\text{pre} + \text{post}}{2}$ | Arithmetic mean of Pre and Post WC | Provisional | **Yes** (blocker: `policyApproval`) |

### 3.2 Unresolved Measurement Decisions
1. **Ratified Road Course Measurement Authority Rule**: Whether international standards (AIMS / World Athletics) require strictly the larger working constant, or whether average/smaller is permissible in specific circumstances.
2. **Provisional Presentation**: The UI now explicitly displays `Provisional` badges on course distance across all screens when the governing policy is not confirmed.
3. **Rollover and Tolerance Invariants**: Automatic counter wrapping and ride-consistency spread tolerances remain designated as pending formal approval.

## 4. Local-First Persistence Design (Part C)

### 4.1 Storage Selection & Architecture
- **Technology**: Native browser `IndexedDB` API wrapped in lightweight, asynchronous helpers in [`src/utils/storage.ts`](file:///media/sda3/Projects/Calibration/src/utils/storage.ts).
- **Zero Runtime Dependencies Added**: Built on native browser APIs without adding bloated third-party libraries. `fake-indexeddb` was installed strictly as a `devDependency` to facilitate Vitest execution in Node environments.
- **Database Name**: `bicycle_calibration_db` (Version `1`).
- **Object Stores**:
  - `sessions`: Keyed by `reference` (`keyPath: 'reference'`). Stores complete session state.
  - `meta`: Keyed by `key`. Stores schema version, last persisted timestamp, and record count.

### 4.2 Hydration Guard & Resilience
- **Hydration Guard**: `isHydrated` state in `SessionContext` prevents initial React defaults from overwriting previously stored user data during startup.
- **Corrupt Record Protection**: `isValidSessionRecord()` validates schema integrity before loading. Malformed records are discarded without crashing the application.
- **Error States**: `storageStatus` tracks storage health (`ready`, `degraded`, `unavailable`). If IndexedDB fails (e.g. quota exceeded or disabled in private browsing), an alert banner is displayed in `SessionBanners.tsx` informing the user that data is kept in memory.
- **Derived Calculation Integrity**: Persisted sessions store only raw inputs, setup parameters, overrides, and audit trails. Derived calculations (`Derived`) are freshly recalculated on hydration using full IEEE 754 precision, ensuring no stale or out-of-sync calculations are ever loaded.

## 8. Remaining Limitations and Recommended Next Phase

### Remaining Limitations
1. **Client-Side Storage**: IndexedDB is local to the device/browser. Client-side storage cannot replace tamper-proof server audit trails or multi-device synchronization.
2. **Measurement Policy Approval**: Official governing rules for final constant selection, course length bounds, and ride-consistency spread tolerances still require formal sign-off from the standard-setting body.
3. **Accessibility**: Modal focus trapping remains candidate for remediation in Phase 3.

### Recommended Next Phase: Phase 3
1. Implement accessibility focus traps in `Modal.tsx`.
2. Codify ratified measurement standard when published by stakeholders.
3. Introduce secure client-side export/backup (JSON/CSV) of stored calibration sessions.
